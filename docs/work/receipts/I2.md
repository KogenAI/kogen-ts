## Integration defects and regression coverage

- The approval loader and Build base reader requested Git output bounds above
  the production supervised port's 900 KiB maximum, so every public Build
  stopped before planning. Both reads now use the supported bound.
  `tests/build-load/load.test.ts` exercises both production constraints.
- Shell recipe requests exposed all seven schemas and the planner instructions
  did not identify the role to a fake provider. The public composition now
  sends its three shell schemas with disabled planner tool choice and the
  role-specific instructions. `tests/build-load/load.test.ts` checks the
  shell/direct schema and authorization mapping.
- Bare origins report a `bare` pseudo-worktree without a HEAD. Landing
  preflight now ignores that record and retains real linked checkouts.
  `tests/landing-rebase/landing-checkout-race.test.ts` exercises a real bare
  origin and a separate working clone.
- The owned ChatGPT path now reads a saved login per request, includes credential
  work in the first-byte deadline, and composes the refresh/replay API with a
  cross-process lock. `tests/refresh-lock/lock.test.ts` checks exclusion and
  owner-only release. The official owned login/list/use/logout case is recorded
  below.
- Queue signals now wait for Build completion and its serialized writer. The
  controller appends `interrupted` with the signal reason before releasing its
  claim, leaving the run pending for I3 recovery. The barrier-style regression
  in `tests/build-entry/build-entry.test.ts` aborts during planning and checks
  the last event, absent `finished`, running snapshot, and released claim.
- Build commands use a dedicated native host bridge. On a queue signal its
  control socket closes immediately, so the native supervisor terminates the
  active child group while the main bridge remains available for durable run
  events and claim release. `tests/host-bridge/host.test.ts` starts a real
  30-second shell and asserts group shutdown in under five seconds.
- Build now resolves the provider-use project account, committed fallback, and
  benchmark overrides before its owned credential request. An unsupported Grok
  selection stops with a provider-unavailable error while its public Build enters
  at I6. `tests/build-load/load.test.ts` covers project and environment picks.
- Build now loads `~/.kogen/config.yaml` and passes its machine role defaults to
  the controller, allowing committed project roles to override them. The
  `tests/build-load/load.test.ts` regression reads a real machine-role YAML
  document through the production loader. The focused conformance recheck of
  `v1.2-126-state-15` is recorded below.
- `provider use` now checks that the selected ChatGPT profile is signed in
  before publishing the account map. The command-level regression in
  `tests/i2-provider/provider-use.test.ts` verifies the login error and zero
  writes for an absent profile.
- An unavailable Build sandbox now records `started.sandbox=unconfined`, a
  reasoned `sandbox_unavailable` event, and the public warning on stderr. The
  controller regression in `tests/build-entry/build-entry.test.ts` checks both
  journal fields; the warning uses the same confined-process adapter as I1.
