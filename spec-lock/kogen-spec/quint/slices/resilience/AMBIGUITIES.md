# Ambiguities, silences and guesses (provider resilience)

1. **Usage-limit stop point.** "Repeat until the usage limit has lasted 6 h in total; then stop." Chosen: each usage_limit error waits (retry_after_ms, else 900000) and adds to `usage_ms`; the stop happens on the next usage_limit error once `usage_ms >= 21600000` (waits are never truncated or skipped). With 3 h waits: wait, wait, stop on third. The alternative (stop on the error whose wait would reach 6 h) is equally plausible. `usage_ms` resets on success.
2. **retry_after_ms = 0 and absent.** Absent is encoded as a negative value in the Attempt event; 0 is a real 0 ms wait (not the default).
3. **What counts as "consecutive" for the switch.** Overload and timeout count together; transport, malformed and usage_limit reset the streak to 0 (prose only says "consecutive overload or timeout"); login does not touch it. A success or a new Request resets it. After a switch the counter is 0 and stays 0 (no second switch, "lasts for the rest of the stage").
4. **Switch also retries.** The switch decision still resends after the normal ladder delay (the 3rd overload gives delay 8000) and journals both provider_retry and provider_switch (order: retry, switch, wait). The retry ladder position is not reset by the switch.
5. **`rung`.** Recorded as the 1-based retry count of the request (1,2,3,...), not capped at 6. Prose does not define it. It is 0 on non-retry events. provider_wait has stage "" (table lists only reason, wait_ms); provider_switch has the stage.
6. **provider_wait scope.** The parenthetical "(provider_wait)" after "Backoff waits do not count" is read as: in Build mode every wait (backoff and usage_limit) records provider_wait (reason = error class or usage_limit, ms = delay); in shaping mode (no budget clock) none. Login refresh resend records nothing.
7. **Outage clock.** Time since the last success = request elapsed time of every attempt + the backoff delays decided; usage_limit waits are excluded (a 6 h usage allowance would otherwise be impossible under a 30 min window). It is checked only on transient errors (overload/timeout/transport/malformed), in Build mode only, strictly greater than the window, before scheduling the retry; the stop reason uses the class of that last error. The prose does not say whether the clock includes backoff waits; scenarios avoid depending on it.
8. **Budget clock.** `budget_ms` = sum of elapsed_ms of all attempts in Build mode; waits excluded. The prose does not say what happens when the budget is exhausted, so the policy does not model any stop for it.
9. **Deadlines.** A missed deadline (first_byte_ms > 120000, max_gap_ms > 120000, elapsed_ms > 600000; equality is within the limit) turns any result, including ok, into timeout. The adapter supplies the measured values; elapsed_ms is charged as given.
10. **Login.** "One forced refresh" is per request (reset by Request); owned mode is a Stage flag; not owned (injected auth file) stops at once. The refresh outcome is a separate Refresh(bool) event; the resend after a successful refresh is `retry` with delay 0 and no journal entry. Expired-JWT login errors are not distinguished from HTTP 401/403.
11. **Stop exit code.** All stops (outage, usage_limit, login, shaping attempts) give exit 4; the prose states 4 for outage, login and shaping only. The "Intent stays queued" consequence is outside this slice.
12. **Shaping.** Same rules; no budget clock, no outage window, no provider_wait; 8 attempts per request counting every attempt; the 8th failed attempt of any non-login class stops with provider/<class>, exit 4. usage_limit waits and the 6 h cap still apply in shaping.
13. **Request vs stage scope.** Retry count, streak, refresh flag, usage total and outage clock are per request; model, switched flag, budget and journal are per stage. Stage resets all, including journal.
14. **Event order refusals** (`no_stage`, `not_sending`, `request_in_flight`, `not_refreshing`, `stopped`, `unknown_class`) are inventions of this spec; they leave state unchanged except `last`.
15. **Error classification (4.4)** is not modelled: the Attempt carries an already classified result. The retry-after parsing from headers is also done by the adapter.
16. **"Identical request"** resend and "no other layer retries" are not observable in this model.
