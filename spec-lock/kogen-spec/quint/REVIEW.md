## Invariants a builder must preserve

1. An approval ref identifies exactly one immutable Intent/test byte pair and is never updated after a failed hash, check, re-read or CAS.
2. At most one live project drain and one live origin claim exist; a second start is harmless, and nonfatal per-Intent outcomes leave later approvals eligible.
3. A landed status implies the landing record preceded a successful base CAS and the candidate commit is reachable from that base; cleanup failure cannot undo it.
4. Every landed tree has been verified on the exact expected parent, with approved sources and protected paths intact. A lost CAS requires re-verification before another attempt.
5. `prompt_cache_key` and `session-id` stay constant within one Build; thread identity changes only with stage/attempt/rung/epoch; prior same-model history bytes never change, and usage never invents cached tokens.
6. All user code runs in a controlled process group and workspace, with no model command or secret in argv and no non-landing write to checkout/origin.
