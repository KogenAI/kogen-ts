# Builder plan: finish conformance from the guaranteed core outward

**Headline:** Build the fixed CLI and the private `kogen-xspec` replay binary from one core library; prove approval → serial queue → verified Git CAS/recovery, then provider login/stream/cache. Add ladder and witness experiments only after the core passes. Estimates are **focused engineer-days** after project scaffolding, excluding live benchmark waiting and OS-specific sandbox debugging. A trace pass is never a substitute for the read-only black-box suite.

## Order and gates

1. **Freeze the public boundary (1–2 d).** Compare the CLI parser/help corpus to `CLI-RULE.txt`; implement both admitted provider names, `chatgpt` and `grok`, on the existing verbs. Run `kogen-conformance` `cli` and `format`, record known v1.1/v1.2 conflicts instead of altering cases. The private adapter binary is separate from `kogen`.
2. **Implement durable approval state (3–5 d).** Hash exact Intent + NUL + test bytes; re-read before CAS; write immutable approval commit/ref; run checks. Run `state`/`approval` plus `approve`/`intent` full traces.
3. **Implement serial queue and status (3–5 d).** Priority/time/slug order, duplicate start, stop, claim, status precedence and crash reconciliation. Run `cli`/`state`/`build` queue cases plus `queue`/`status`/`recovery` traces.
4. **Implement gate and landing (4–7 d).** Use the approved package, verify the candidate on the expected base, write landing record/incoming ref, CAS, re-verify after a moved base, reconcile crashes. Run real Git/custody cases and `rebase` traces. Only the green gate is a required release rule; selector/demotion traces remain diagnostic.
5. **Implement ChatGPT and Grok providers and caching (4–7 d).** Own login/use for both admitted provider names, fake OAuth/SSE, retry classification, stable cache affinity, append-only prompt history, and usage accounting. Run `provider`/`custody` cases and `stream`/`session` traces, plus the §4.10 Grok request cases, then a credential-safe live three-turn cache smoke. The D49 gate is >95% cached input on each third-and-later turn; report raw numerator, denominator, missing warm records and host/model.
6. **Version the v1.2 black-box delta (2–4 d).** In the conformance repository's own change process, add fixed-CLI help, test-byte hash, byte-prefix, cache-key/header, missing usage, and post-CAS crash cases. Keep the currently supplied suite read-only in this task. No v1.2 release claim until the new suite version and all guaranteed slices pass.
7. **Promote only measured optional behavior.** Ladder, selector, shaping ledger, setup cache, witness, edge probes and context checkpoint need the evidence in `CLASSIFICATION.md`. An L/E slice can be run for diagnostics without blocking core release.

## Reporting template

For every mandatory slice, record: implementation SHA, adapter SHA, full hand count, generated trace count/steps/seeds (17, 23, 41), first divergent event/field, and the black-box case IDs tied to it. A `--project` replay is labeled **diagnostic projection** and cannot increment the pass count. A `no_seam` response is a failure. For a spec/test disagreement, fix the prose and hand scenario first, regenerate goldens from Quint, then change the adapter or implementation. Run all steps with an empty temporary HOME and the fake provider; never run installed Codex or pi on credentials to measure caching.
